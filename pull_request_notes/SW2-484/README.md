# Scheduler Core Refactor — engineering study pack

A study pack for an engineer joining the scheduler team. It explains how the `scheduler` ROS 2 package turns a list of jobs into a timed, dependency-ordered schedule, and then what the Scheduler Core Refactor changes.

| Read | For | Time |
|---|---|---|
| [01 — Software background](01-software-background.md) | How the software works: node and interfaces, garage model, `Plan()` step by step, events and the DAG, job expansion (with a 2D garage example for every job type), tray and AGV assignment, motion planning, bays. 43 figures, annotated code snippets, a design FAQ (DAGs vs Open-RMF, parallelism, why the logic is shaped this way), checkpoint questions | 4–5 h in three passes |
| [02 — Issue and proposed design](02-issue-and-proposal.md) | What the two assignment algorithms are coupled to today (generated matrix), the proposed solver interfaces, staged plan and risks | 45 min |
| [03 — Verification and benchmarks](03-verification-plan.md) | What the 72 existing tests cover, gaps, the parity comparison and benchmark method | 30 min |

Doc 01 opens with a reading plan and a table of the names and types used in every code snippet. Each snippet says which class it is in and what `this` refers to.

## Conventions

Math uses Markdown LaTeX compatible with typical VS Code math previews: `$...$` inline and `$$...$$` for display; *italic lowercase* symbols are scalars, **bold lowercase** symbols are vectors, and **bold uppercase** symbols are matrices. Each new quantity is defined in the surrounding text or symbol table. A symbol is written immediately next to its descriptive noun, e.g., “the travel time $t_{ij}$”. Code identifiers are kept in code font because they are literal C++ names, not mathematical variables. Units are shown for geometry and time. All figure axes and scales are marked illustrative unless grounded in layout source data.

## Figures

All figures are generated by one script and share one visual system:

```bash
pip install fonttools brotli pyyaml
python3 scripts/diagrams/build.py          # every figure + figures/viewer.html
python3 scripts/diagrams/build.py 13 15_   # only figures whose file name starts with these
```

- **Hand-authored SVG, measured text.** Labels are measured with the real font metrics and the canvas is sized from what was drawn, so nothing is clipped or runs past the border. The build prints a warning if any two labels overlap.
- **Fonts embedded.** The used glyphs of JetBrains Mono (code) and IBM Plex Sans (prose) are subset and embedded as WOFF2, so a figure looks the same in VS Code, GitHub and browsers. Licences: `scripts/diagrams/fonts/`.
- **Pan / zoom.** Markdown previews render SVGs as static images. `figures/viewer.html` is an offline gallery with scroll/pinch zoom, drag to pan and arrow-key navigation; any `.svg` opened directly in a browser also gets zoom controls.
- **Theme.** Palette from the ui-ux-pro-max-skill *Developer Tool / IDE* colour set (dark slate surfaces, green accent) with sky / violet / amber / teal / pink as categorical colours; typography from its *Developer Mono* pairing. Tokens live in `scripts/diagrams/theme.py`.
- **Status badges.** Every figure says what it is: `AS-BUILT`, `PROPOSED · NOT IMPLEMENTED`, `ILLUSTRATIVE`, `SCHEMATIC`, `CONCEPTUAL · NOT IN PECOS YAML`, or `YAML GEOMETRY · HYPOTHETICAL OCCUPANCY`.
- **Pecos maps** read `sources/5675_pecos_combined.yaml` directly (28 nodes, 37 edges). Stalls are drawn with the layout's XL parking window; AGVs, trays and payloads are always hypothetical.
